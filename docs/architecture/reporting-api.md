# Reporting API and exports

`GET /api/v1/organizations/{public_id}/reports` uses the existing authenticated tenant middleware, `reports.view`, report-specific gates and existing rate limits. No report creation/status/public-link endpoint exists. Optional `format=csv|xlsx` returns an authenticated attachment; otherwise the standard `{data: ...}` JSON envelope applies.

Required `report`: revenue, settlement, activity, expiry, attendance, occupancy, cancellations, popularity. Optional fields:

- `from`, `until`: paired inclusive YYYY-MM-DD, 2001–2100, maximum 366 days; default studio current month through today.
- `granularity`: daily/weekly/monthly. `comparison`: none/previous/custom; custom requires compare_from/compare_until, at most 366 days, years 2000–2100. Two ranges at most 732 days.
- `group_id`, `trainer_id`: visible operational public UUIDs; `plan_id`: tenant plan UUID for revenue/settlement/expiry. Unsupported combinations reject 422; concealed foreign or inaccessible references return 404.
- `currency`: MKD only. Settlement `state`: active/upcoming/expired/cancelled; `payment_state`: unpaid/partially_paid/paid/overpaid. Expiry `expiry`: expired/7/14/30/later.
- Popularity `rank`: present/reserved/waiting. `top`: 1–50, default 10. `view`: summary/details. `page`: 1–10000; `per_page`: 1–100, default 25.

Unknown fields are rejected, including actor/tenant IDs, client totals, SQL grouping, as-of tokens or file paths. Normal validation/error envelopes apply. Permission loss returns 403/404 according to existing context resolution; a changed scope detected at final authorization returns 409. Bound failures return 422. Audit/storage/server failures produce no export bytes.

Responses contain totals, columns, rows, optional dimensions/pagination, comparison and metadata: GT017.1, organization public ID, validated filters, resolved dates, timezone, Monday week convention, half-open interval, currency/unit, fixed clock, freshness, explicit current-state/period basis, comparison dates, limitations and server correlation ID. Option lists contain at most 100 visible choices plus a truncation flag. Operational rows never include member identity. Financial/current-member details use independently required domain gates.

## Snapshot and authorization boundary

`OperationsDirectory::snapshot` opens read-only REPEATABLE READ. All rows, buckets, options, comparisons and export preparation share it. SQL statements are bounded to 15 seconds, total preparation to 30 seconds, incremental memory to 128 MiB and completed file size to 25 MiB. Detail exports count before bounded retrieval (maximum 50,000); file writing is incremental but row retrieval is a bounded in-memory result, not an unbounded stream. No business rows or organization lock are held for aggregate reading.

After reading/preparing the private file, a short `Lifecycle` transaction takes the existing organization lock, re-resolves current authority, compares role/grants/location/timezone fingerprint, and writes audit evidence. Membership/grant revocation committed before that check denies output; a concurrent writer after it is ordered after the authorized response. Current session assignment is evaluated within the read snapshot, so an in-flight report may contain the old valid assignment snapshot; subsequent requests use the new assignment. Bearer token/session authentication is performed by existing middleware at request entry; the final Lifecycle check re-resolves membership/grants but does not independently reload an already-authenticated bearer token. Token revocation during that in-flight request is therefore ordered after its initial authentication; subsequent requests are denied. Already delivered bytes cannot be revoked. This is not a claim of impossible instantaneous revocation.

There is no cross-request cache, persistent download token, background export job or publicly served file. Synchronous retry is a fresh separately authorized snapshot, with separate bounded audit evidence. Duplicate-job ownership is therefore inapplicable.

## Export format and lifecycle

CSV: UTF-8 BOM, CRLF, RFC-style quoted values, stable machine keys plus localized header labels, `_row_kind=metadata|data`, JSON report/comparison metadata. Empty exports retain headers and metadata. Numeric money is signed minor-unit integer text. Untrusted strings beginning with formula/control prefixes are quoted as literal spreadsheet text.

XLSX: genuine OOXML generated by OpenSpout, Report/Metadata/Totals and optional Comparison worksheets; bold localized machine-key headers, freeze row, filter, usable widths. Identity/untrusted strings always use literal string cells, never formulas. Money up to 15 digits is numeric; larger exact integers remain strings. No macros, external links or provider content.

Private storage is `storage/app/private/report-tmp` (directory 0700, output 0600), random server-generated names, fixed safe response filenames, `no-store, private` and `nosniff`. A fully prepared file is reauthorized/audited before response. Successful response deletes the server file; exceptions remove it; interrupted leftovers expire after 24 hours through explicit/opportunistic cleanup. Native retrieval has a 30-second deadline, account-generation guard and 25-MiB bound; tokens stay in headers and files exist only in app-private cache for sharing.

Audit matrix: successful JSON → `report.viewed`; completed authorized export → `report.export_prepared` + `report.download_started` in one transaction. Download-start means handoff to the response, not proof the operating system saved every byte. Events include bounded report/version/filter/timezone/currency/as-of/row-count/correlation metadata, not report rows or names. A failed audit rolls back and fails closed, deleting the file. Denied requests follow existing error handling; there is no additional PII-rich rejection log.
