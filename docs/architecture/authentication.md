# Authentication

Web administrators/trainers use Laravel's session guard through same-origin requests and Sanctum stateful API support. React never stores bearer tokens. Before POST, the API client obtains `/sanctum/csrf-cookie` and sends the decoded XSRF cookie in `X-XSRF-TOKEN`. Session cookie: HttpOnly, SameSite=Lax, encrypted database payload, 120-minute idle lifetime, host-only by default. Local HTTP explicitly disables Secure; production forces Secure. Login regenerates the session ID; logout invalidates the session and regenerates the CSRF token. No remember-me flow, registration, social login, or default password is enabled.

Users' emails are trimmed and lowercased on write and authentication/recovery input. PostgreSQL checks canonical storage and uniqueness. This does not merge provider-specific aliases or strip `+` tags. Passwords use Laravel's hashed cast and bcrypt with 12 rounds locally (4 only in isolated tests). Login input and password lengths are bounded.

Login has independent limits of 5/minute per normalized account hash and 30/minute per IP; all attempts count. Recovery has 5/minute per IP plus the broker's 60-second issuance throttle. Generic failed login and recovery messages avoid explicit account-existence disclosure. Distributed denial-of-service, timing equalization with real mail and MFA require deployment-stage review.

Password reset uses Laravel's broker and hashed, expiring, single-use reset tokens (60 minutes). New passwords require 12 characters, mixed case, number, symbol and confirmation. It rotates the remember token and revokes persisted sessions and Sanctum tokens. Production requires database sessions. Keep sessions on the same PostgreSQL connection for atomic revocation; changing session architecture requires a reviewed migration. No credentials are logged. Notification URLs use configured APP_URL rather than request Host; token/email are in the URL fragment so the browser does not send them in page URLs or Referer headers. The React form submits them in the POST body.

Local mail is the non-delivering array transport: reset flow and notifications are tested, real email delivery is deferred. Do not switch to a log transport, which would write reset credentials into logs. Before enabling mail, localize notification content, verify trusted HTTPS origin/provider configuration and rate-limit behavior.

Sanctum personal access tokens and their hashed PostgreSQL storage are installed for future native clients, with a maximum 30-day lifetime. No mobile token-issuance, refresh, device-management or mobile login UI is exposed. Future tokens need narrow abilities, device-scoped revocation and secure OS storage. Organization Gates intersect token abilities with current organization membership permissions; a token never grants membership or higher privilege. `/me` exposes the holder's own minimal profile and organization picker list. Future member identity/access is distinct from staff grants.
