# GT-015 security review

Reviewed the GT-015 diff against `5446160306f243138f6fb18380bb6cc73e4f40c3`, with supporting authentication, lifecycle, recipient, allocation and mobile session code. No confirmed vulnerability remains from this review. This is bounded review evidence, not proof that every deployment or provider interaction is safe.

## Manual review

- Tenant and recipient access derives from authenticated User through TenantContext, MemberContext or RecipientAccess. Announcements require current all-location `organizations.manage`, rechecked under the organization lock. TrainerProfile and member accounts confer no new staff access. Device, announcement and source UUIDs are tenant qualified; protected ownership fields cannot be mass assigned.
- Device tokens are encrypted, excluded from serialization and never logged. An immutable hash-to-account ledger prevents reassignment even after revocation. Login-token deletion nulls registration credentials, and delivery checks current login validity. Native cleanup captures the original bearer and invalidates late registration work. Account/studio switches clear private cache and navigation. Offline logout and already accepted pushes remain transport limitations, not a claim of remote revocation.
- Push content is generic translated text with a fixed-format notification route. Native parsing rejects arbitrary URLs, malformed IDs and activation/reset capabilities. Taps fetch currently authorized API data. Web and native text rendering do not evaluate announcement HTML. Laravel email is a text template; destination is the verified account email, never a staff-entered contact address.
- Provider endpoints are fixed HTTPS, redirects disabled and response/error data reduced to finite classes. Default external adapters refuse nonproduction execution. Queue jobs contain internal IDs and sanitize failures. The existing API limiter and additional write limiter bound abuse-sensitive requests.
- PostgreSQL uniqueness, source/destination checks and immutable evidence triggers supplement application validation. Organization/delivery locks and leases protect claims; receipts have durable per-attempt identity. Domain rollback leaves no outbox records. External acceptance before database persistence remains an explicitly documented at-least-once boundary.
- Reminder/expiry policy still comes from GT-014. Cancellation, stale sessions, preferences and current recipient eligibility are rechecked. Announcement fan-out has bounded batches and a durable cursor. Reservation capacity, FIFO, attendance, financial snapshots and append-only business evidence remain authoritative.

The review identified a registration-limit robustness defect: reactivation skipped the limit, and different-studio registration could race. The final writer adds an account advisory lock and applies the limit to both creation and reactivation, excluding only the current row. A regression test covers reactivation at the cap. Final manual review also verified restoration of original error-code checks on clean migration rollback. Neither issue established a cross-user vulnerability in the captured diff.

Provider tests use HTTP fakes and Laravel Mail fakes. Populated migration/regression tests supplement an empty development baseline. Exact final counts and commands are in the completion report.

Those require separate environment acceptance. No secrets, external account access, deployment or Git push was performed. Dependency audits and repository secret checks are separate evidence, not a substitute for this architecture-aware review.
