# GT-001 security baseline and review

Implemented controls: framework password hashing/session authentication; canonical-email constraint; login/recovery/API rate limits; CSRF; session rotation/invalidation; broker reset/token/session revocation; explicit membership-scoped tenant context; independent default-deny permission Gates and token intersection; allowlisted serialization; fillable field restrictions; bound Eloquent queries; UUIDv7 external IDs; mk/en errors; no-store auth/API responses; CSP, same-origin referrer policy, nosniff, frame denial and Permissions-Policy; production secure cookies/debug disable/HSTS; ignored private random environment secrets.

React renders text with normal escaping. There is no dangerouslySetInnerHTML or user-supplied HTML. CSS uses local system fonts and built assets; no external analytics/CDN code. Local Vite CSP exceptions apply only under APP_ENV=local. Do not reuse them in production.

Exceptions log only their class, not message, request, headers, bindings, URLs or backtraces. This reduces diagnostic detail intentionally. Future correlation IDs and safe event codes can improve diagnostics without copying personal data. Local mail uses array, not log. Reset URLs use trusted APP_URL and fragments. Do not add request-body/token/password logging; production web-server access logs must avoid sensitive query strings. Framework failed-job records can contain payload/exception detail; no application jobs exist yet, and each future job must review/redact its payload/failure handling before use.

Dependency audits (`composer audit --locked`, `pnpm audit`) fail CI on advisories rather than suppressing them. Both direct and transitive packages are lockfile-pinned. pnpm package install scripts are disabled by .npmrc; current build tools work with shipped binaries. `scripts/secrets-check` detects common key/token/env patterns and accidental generated/private tracked files without printing matched values. It is a bounded practical scanner, not a claim of exhaustive secret detection.

A separate read-only architecture pass informed threat-model.md. Its session-revocation configuration caveat was addressed: reset now uses configured session connection/table, and production enforces database sessions. Future production must keep sessions on the same database connection for transactional guarantees. Prefixes on shared Redis are collision avoidance, not ACL isolation. There is no RLS and no implied safety for future unscoped queries. These limits are documented rather than represented as completed controls.

Not a penetration test or certification. Real delivery, production transport/proxies, MFA, audit persistence, role provisioning, backups, member access and business-write controls remain deferred. See threat-model.md and the domain invariant documents.
