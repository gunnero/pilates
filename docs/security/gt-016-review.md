# GT-016 focused security review

Architecture-aware manual review covers the final OperationsDirectory, OperationsController, OperationsAccountController, strict request classes/routes, web effects/actions, native client/credential lifecycle, and owning Attendance/Allocation/Lifecycle/SessionDirectory/FinanceDirectory boundaries. This is not a generated scanner report and does not claim exhaustive repository coverage.

- **Tenant and assignment IDOR:** all operation entry points resolve authenticated TenantContext and explicit staff/session/attendance gates. Session queries intersect tenant, selected locations and current trainer assignment; profile member IDs must belong to that tenant and session. Summaries, financial participants and alerts reuse the same scoped query. Foreign/trainer filter IDs cannot broaden it. Direct/foreign/revoked/selected-scope tests cover denials and zero-count disclosure. Attendance anti-join subqueries also carry explicit tenant restrictions.
- **Financial exposure:** field projection occurs on the server. Membership-only grants never receive payment status, balances or agreed amounts. Trainers get no implicit financial read. Tests exercise unpaid/partial/reversed balances before removing payment permission. Communication aggregates additionally exclude Trainer roles and require all-location organization management.
- **Credentials:** staff native tokens use explicit ability caps and current database gates, an independent SecureStore key/client, existing per-email account locking, expiry, limits, audit and revocation. Member tokens fail staff access for a dual-role account. Staff tokens fail member account access. No wildcard, plaintext credential storage, browser-token injection or device registration reuse is introduced.
- **Stale state and conflicts:** operation reads are not command authorization. Existing mutation services re-resolve grants under organization/session locks, including assignment changes. Native generations and abortable web reads discard old responses; logout/context changes clear visible state. Duplicate taps are serialized natively; owning attendance idempotency remains authoritative. Conflicts refresh roster state rather than reporting success.
- **Input and resource bounds:** UUID filters, finite status/kind values, inclusive 31-day ranges, pagination caps, bounded profile history, bounded alerts and 31-day communication windows. Roster search uses JSON bodies and parameterized escaped ILIKE. No arbitrary SQL/order, mass assignment or source/actor selection. Waiting ordering remains canonical.
- **Data and audit:** no domain writer was added in dashboard controllers. Existing attendance audit/outbox coupling remains in the same transaction. Walk-in badges project only existence of bounded immutable audit evidence, never metadata. Reads are no-store and do not send messages. Provider state is not described as physical receipt.
- **Preservation:** migration history and grants remain unchanged; no development database reset/migration, Redis flush, external delivery, shared-service configuration or production operation is needed. Existing backend/browser flows remain in the required regression suite.

Issues found during implementation and addressed: initial native response ownership/duplicate-action handling was isolated in OperationsClient; obsolete web context responses are ignored; attendance conflicts now refresh their containing operations counts; communication totals cannot bypass trainer assignment scope; oversized roster selectors were constrained for tablet/phone layouts. Conflict messages are retained independently of successful background reloads, fixing an existing attendance regression caught by the full web suite. Staff web follow-up URLs validate requested organization IDs against the authenticated account before resolving context. Baseline formatting failures in five test files were corrected without changing assertions. Newly reported baseline CommonMark advisories were resolved with the narrow 2.10.1 → 2.10.3 patch update; Expo/Camera/Constants received the three direct compatible patches required by Expo Doctor, with Expo’s matching transitive modules-core patch. The existing settings browser test used an ambiguous language selector that could also match the studio locale field; it now scopes the selector to the top banner without changing its assertions. Delayed native SecureStore restoration cannot overwrite a newer login, and app resume invalidates in-flight profile responses before refreshing; both have explicit native regression tests. No advisory suppression or test threshold change was introduced.

Inherited limitations remain: database-owner credentials can bypass application boundaries; future queries must preserve scope; an offline logout cannot prove remote revocation; accepted provider messages cannot be retracted; no physical-device/provider verification is claimed. The GT-004 review's stale generated coverage bookkeeping is not evidence for this change; this review follows the actual GT-016 code and tests.
