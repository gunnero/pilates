# GT-002 focused security review

Scope: the incremental migration, models, tenant context, lifecycle services, operator commands, controllers/requests, explicit response fields, React management/switching and regression tests. This is a source review with PostgreSQL/browser verification, not a penetration test or certification. A separate read-only architecture pass independently reviewed tenancy, grant escalation, owner locking and audit evidence. Existing authentication, password reset, headers and host boundaries remain from GT-001.

| Area                        | Review result and evidence                                                                                                                                                                                                                                                             |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Issues found and resolved during implementation:

1. Administrator default grants initially omitted attendance.view while default Staff held it. The grant-subset rule correctly blocked administrators from suspending Staff. Added the nonfinancial attendance grant to the explicit administrator bundle and verified the authorized transition. Financial separation remains unchanged.
2. Operator ownership bootstrap initially omitted old selected-location scope/assignments from evidence. Included those prior values before clearing assignments.
3. A 4096-byte audit cap could reject valid maximum-length multilingual before/after location values. Raised the finite cap to 8192 bytes and added a maximum-length multibyte regression test.
4. The staff editor could submit an empty permission set when an actor had permissions.manage without permissions.view. It now preserves undisclosed grants on status-only edits; a component regression test covers that independent-permission combination.
5. The timezone trigger alone checked only new writes. The migration now passes pre-existing organization rows through it, so invalid legacy zones fail migration instead of persisting silently.

No unresolved exploitable tenant bypass, privilege escalation or supported-writer owner race was established by this review. This conclusion is scoped to the inspected paths and tests, not a guarantee for future modules.

Remaining boundaries: no RLS; all new queries must scope explicitly. Direct trusted SQL does not enforce aggregate owner count or append audit automatically. Host operators can bootstrap ownership only when none remains, but are intentionally outside user Gates and must be trusted. Shared Redis prefixes are not ACL isolation. Production DB privilege separation, retention/export, MFA, real mail, public hosting and safe job payloads remain deployment/future work. See [threat model](threat-model.md).
